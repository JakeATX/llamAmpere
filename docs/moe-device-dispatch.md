# Experimental GPU expert-cache dispatch

`GGML_MOE_CACHE_DEVICE=1` opts into device-side dispatch for the runtime MoE cache. It is off by default. Use the normal expert-cache configuration as well. This path preserves every selected expert and the original compressed weights; it does not skip experts or substitute a lower precision weight format.

At an idle boundary, `ggml_backend_sched_moe_cache_device_prepare` publishes one stable address table per expert tensor. Each entry points to a resident cache slot or an exact CUDA-addressable host copy. The CUDA MUL_MAT_ID kernel reads expert IDs and resolves addresses on the card. Hits need no host routing readback, per-expert stream synchronization, activation download or result upload. Cold entries currently read mapped pinned RAM; asynchronous miss staging is a separate feature.

The initial implementation supports one CUDA device on Linux. Preparation validates tensor shapes, types, allocation sizes and host/card headroom. Unsupported shapes and IQ1_M keep the existing exact CPU/cache path. Preparation can be expensive on drivers that cannot register a read-only model mapping: exact pinned copies are allocated for nonresident weights. That setup cost and host memory pressure must be included in request timing.

`GGML_MOE_CACHE_DEVICE_CAPTURE=1` separately opts into CUDA graph capture. A globally unique preparation generation invalidates cached graph executables when a table is released, replaced or belongs to another session. All table and slot addresses remain fixed while graphs reference them. The scheduler rejects stale device assignments rather than copying a complete host expert bank to the card.

Adaptation runs only when no graph scope or expert node is active. `GGML_MOE_CACHE_DEVICE_ADAPT_INTERVAL` sets the boundary interval (1-1024 scopes, default 64). `GGML_MOE_CACHE_DEVICE_ADAPT_MB` caps attempted copy bytes at each boundary (1-1024 MiB, default 64). Evicted entries first receive a stable exact host fallback. When available, promotion reads the retained pinned copy instead of faulting the original file mapping back into RAM. Trimming, warming, teardown and source invalidation retire prepared tables before changing ownership.

`GGML_MOE_CACHE_DEVICE_STATS=1` enables device hit/miss/dispatch counters and periodic diagnostic snapshots. Snapshots synchronize and can affect timing. Legacy host-dispatch counters exclude device-routed work. A cache hit rate must use device counters when device dispatch is active.

The cache tests cover supported compressed types, mixed resident/mapped routes, strided routing IDs, read-only source mappings, host budgets, adaptation, source reuse and graph lifetime across preparation generations. Passing those checks does not establish a model speed improvement. Keep this feature opt-in until full-protocol comparisons pass.

`GGML_MOE_CACHE_DEVICE_FUSED=1` additionally combines compatible gate/up projections and SwiGLU into one GPU operation, sharing activation quantization. It requires device dispatch, matching projection types/shapes, the same activation and routing inputs, and a safe graph dependency pattern. Both expert address tables stay independent; every selected expert still contributes. Other patterns use separate exact operations. This option is off by default. Tests compare all22 supported mapped formats with a CPU reference, cover independent resident/cold banks and strided routing, and require byte-identical repeated GPU output and actual captured-graph replay.

`GGML_MOE_CACHE_DEVICE_PUBLISH_ASYNC=1` queues changed address tables and hot bitmaps on the existing adaptation stream and waits once before the next graph scope. It is off by default. Expert selection, copy limits, weight bytes and stable table addresses are unchanged. `test-moe-cache --device-publish-async-only` checks captured replay, tuned adaptation and the multi-pool starvation fixture on this path.

`LLAMA_MOE_PERMANENT_MIB=3072` opts into model-owned permanent original expert copies on CUDA. It requires the anonymous expert arena and a valid `GGML_MOE_CACHE_PROFILE_LOAD` profile. Startup verifies the profile against the original weight bytes, ranks its used experts, copies up to the requested budget to a separate immutable GPU slab, and releases only fully covered host pages after safely registering the cold complement. The final layer stays in host memory for output-only CPU prompt work. An invalid profile, inadequate GPU capacity, or failed pin transition refuses the option. The default is off.

`GGML_MOE_CACHE_PROFILE_BLEND_PCT=1..100` optionally retains a saved profile's influence when seeding the cache after a long prompt. Each tensor's profile and prompt counts are independently normalized, then mixed with the requested percentage assigned to the profile. The resulting scores rank the initial pool contents and lending survivors; decode swap scores adapt independently unless a profile prior is enabled. A value of 100 seeds entirely from the saved profile. Unset or 0 preserves the existing prompt-first ranking, with profile entries used only after prompt-observed entries. This option requires a valid loaded profile and does not change the saved counts, permanent allocation, pool capacities, routing, or weight bytes.

`GGML_MOE_CACHE_PROFILE_GLOBAL=1` optionally allocates the expert grant from the saved profile instead of fixed per-type shares. It ranks each `(layer, expert)` bundle of available projections by raw profile use weighted by projection bytes, divided by total bundle bytes. All projections in a selected bundle get slots together; each pool retains at least 64 slots. Raw counts preserve output-pruned final-layer frequency. The plan stays within the current expert byte grant, with unused bytes reported when another complete bundle does not fit. Scratch and table workspace reservations are unchanged. Allocation failures may reduce actual capacities, which are logged beside planned capacities.

`GGML_MOE_CACHE_PROFILE_GLOBAL_DENSITY=1` optionally changes global profile ranking to logical route count per real expert byte. It averages the saved counts across a bundle's projections, then divides by the sum of their actual byte sizes. Counts are not normalized by per-tensor totals. Complete bundles, the current byte grant, the minimum 64 slots per pool, and all existing allocation fallback checks stay the same. The planner logs the selected objective. This option requires `GGML_MOE_CACHE_PROFILE_GLOBAL=1`; unset or 0 preserves raw-frequency ranking.

Global mode requires a valid loaded profile and complete tensor discovery. Generic single-projection names are supported as independent bundles. Unusable plans fall back to the default allocation. Profile counts and plan keys are owned by the session and invalidated with their source tensors. A rebuilt post-prompt session reloads the profile and computes a plan for its actual grant. A same-session warm recomputes pool capacities within its current resident byte budget after waiting for idle work and releasing device tables; donor pools shrink before recipient pools grow. Permanent slabs are separate and unchanged. Global mode seeds startup and post-prompt warm from the selected saved-profile bundles; it overrides prompt counts and `GGML_MOE_CACHE_PROFILE_BLEND_PCT` and logs that choice. Pool capacities and the warm seed change; routing, weights, and default behavior do not. Decode swap priors are a separate option. The planner currently prices permanent-resident slices as runtime slices. Combining global and permanent residency stays lossless, but can allocate runtime capacities inefficiently and admit partial extra bundles after permanent entries are skipped. Global placement measurements use `LLAMA_MOE_PERMANENT_MIB=0`; later independent swaps can also split runtime bundles.

Permanent copies survive runtime-cache suspension, trimming, adaptation, and B1 prompt streaming. Device tables always overlay their original GPU pointers; B1 copies them directly on its GPU copy stream. The runtime cache spends its remaining capacity on other experts. Generic transfers and CPU graph execution restore missing original host bytes from the GPU before reading them, with a `permanent host restore` log. A restore uses a startup-allocated staging buffer capped at 8 MiB, reads no disk, and repins the restored hole pages. Weight mutation while permanent storage exists is rejected. A RAM-fit measurement must check that no host restore occurred during the measured prompt and generation.

`test-moe-cache --permanent-host-only` checks generic and CPU read barriers without a GPU. `test-moe-cache --permanent-residency-only` verifies original GPU bytes, direct device copies with discarded host sources, and exact host restoration with a small validated profile. It also checks numerical device-table replay, adaptation, trimming, and session recreation while full permanent host pages are absent.

`GGML_MOE_CACHE_PROFILE_PRIOR_PCT=1..1000` adds a normalized per-tensor profile prior to decode swap scores (100 means the same total score mass as the causal per-tensor route EMA). The first observed swap count snapshot calibrates the prior in steady EMA units; subsequent snapshots update that scale without using future routes. The default keeps this prior throughout decode. `GGML_MOE_CACHE_PROFILE_PRIOR_DECAY=1` instead seeds it once and decays it at the swap policy rate. Unset or 0 retains the original zero-seeded adaptive scores. A valid loaded profile is required. These options change placement only.

`GGML_MOE_CACHE_SWAP_WHOLE=1` opts into coherent decode swaps of complete up/gate/down expert bundles. It requires `GGML_MOE_CACHE_SWAP=1`, exact `blk.N.ffn_{up,gate,down}_exps.weight` names, complete layer triplets, and no partially resident starting bundles. It logs initial complete/partial counts and falls back to the slice policy if those checks fail. Pairing requires matching ordered projection types, sizes, and matrix shapes; compatible layers can exchange complete bundles. `GGML_MOE_CACHE_SWAP_LAYER=1` restricts pairing to the same layer. Permanent slices cannot be victims. Candidate scores are the mean of the three projection scores, with at least 2 route-count units required for admission. All three victim fallback addresses and replacement slots are checked before any eviction; each bundle lands through the existing exact copy and publication protocol. No additional expert VRAM is allocated.

`GGML_MOE_CACHE_SWAP_MAX` still counts projection slices (use 288 for 96 whole experts), and `GGML_MOE_CACHE_SWAP_MB` still caps copied bytes. A bundle is admitted only if all three slices fit both limits. `GGML_MOE_CACHE_SWAP_MARGIN_MILLI=1500` sets the gain margin to 1.5 and overrides the integer margin option. `GGML_MOE_CACHE_SWAP_DECAY_AFTER=1` accumulates recent counts, selects swaps, then applies decay; the default applies decay before adding recent counts. These options are off by default. `test-moe-cache --swap-whole-only` checks cross-layer whole replacement, exact output, actual swaps and hits, slice and byte caps, incompatible matrix shapes, malformed-name refusal, and same-layer restriction on a small CUDA fixture.

`GGML_MOE_RESIDENT_UPLOAD=1` opts generic one-dimensional asynchronous uploads and scheduler weight copies into the permanent copy path. A mixed source range uses exact GPU bytes for permanent spans and the original RAM for cold gaps, on the destination stream. Asynchronous tensor copies synchronize the source backend first; scheduler copies use immutable weights after the destination's existing event wait. Unsupported destinations, synchronous transfers, two-dimensional transfers, and CPU reads retain the host restore barrier. This option is off by default; operator correctness does not establish sustained model RAM savings.

`test-moe-cache --permanent-scheduler-cpu-only` uses a synthetic resident provider and separate CPU-backed buffer types to exercise scheduler copies, repeated uploads, destination reuse synchronization, and fallback barriers without a GPU. `test-moe-cache --permanent-scheduler-events-cpu-only` separately checks parallel scheduler event waits, recorded-event reuse, user-input event synchronization, and event cleanup with CPU-backed synthetic events. `test-moe-cache --permanent-scheduler-rotating-cpu-only` checks all parallel copy slots through two asynchronous CPU replay cycles and wraparound, including the one-to-one association between destination storage and the waited event. It also covers reallocating leaf storage when a user input rotates from an externally allocated slot. Synthetic CPU execution does not prove CUDA stream ordering. `test-moe-cache --permanent-host-only` checks generic and CPU read barriers without a GPU. `test-moe-cache --permanent-residency-only` verifies original GPU bytes, direct device copies with discarded host sources, and exact host restoration with a small validated profile. It also checks numerical device-table replay, adaptation, trimming, and session recreation while full permanent host pages are absent.
