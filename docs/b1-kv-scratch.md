# Borrowing unused context memory during B1 prompts

Both controls below are experimental and disabled unless explicitly set.

`LLAMA_B1_KV_SCRATCH=1` allows a cold, single-sequence, one-pass legacy B1 prompt to borrow aligned GPU ranges from unused layers and unused cell suffixes. It requires `LLAMA_B1_LAYER_RESERVE=1` and `LLAMA_B1_FFN=0`. The largest measured layer graph still has a conservative preflight reservation; borrowing reduces per-layer owned compute allocations during execution. It does not yet reduce that initial preflight peak. Actual savings depend on contiguous tensor sizes and allocator fragmentation; a failed reduced-size graph probe retries with the full measured owned size.

The next layer first synchronizes and invalidates old graph captures, then unbinds its borrowed views. Live KV prefixes and staging rows are never offered. Host-backed resident bodies, multiple streams, pending shifts, copied streams, and unsupported layouts are excluded. Views are also returned on failure, before generation, and during context destruction. Returned views are cleared before attention can read masked padding. Serialized shared helper compute is supported after the existing B1 handoff synchronizes the helper, detaches its donor, invalidates its allocator, and marks it for a new reservation. Helper device-prefill hidden rows use independent storage. An asynchronous helper or configured helper KV scratch still disables this option. Warm prompts and other unsupported cases use the existing path.

Plain-cache suffixes protect the padded physical occupied-cell frontier as well as the prompt token count. A cold logical sequence in a reused cache may occupy a nonzero physical offset; those cells and any masked attention padding remain protected.

`GGML_CUDA_MOE_CACHE_RETURN_RESERVE_MB=1536` optionally lowers the runtime expert cache's free-memory margin when prompt scratch is returned after an actual expert-cache loan or a suspended pool is recreated. Startup warmup restores cannot lower it. The initial setting `GGML_CUDA_MOE_CACHE_RESERVE_MB` still applies while models and helper contexts load. The new value must be at least 1536 and no greater than the initial setting. A different live session's larger margin still wins. Reducing the margin may admit more exact expert slots through the existing survivor refill; it does not skip experts or alter KV precision.

For validation, `test-sjkvarn-state --scratch-views` writes through the offered views and checks protected bytes, and `test-moe-cache` checks that two live sessions retain their maximum reserve. CUDA and model gates, exact saved-cache checks, and full BEST_CONFIG measurements are required before enabling either control. The task-local runner `scripts/bench-fnkvwin-borrow.py` snapshots the shared BEST_CONFIG launch inputs, records loaded library hashes, separates sampled prompt and generation peaks, and stops on the owner's memory, power, hit-rate, and disk-page alarms. Use a frozen executable named `llama.cpp-*` beside its frozen libraries and run under a task-named systemd unit with the GPU lock held by its parent.

`scripts/run-fnkvwin-borrow-pairs.py --server FROZEN_SERVER --out NEW_GATE_DIR --model-result PASSED_MODEL_RESULT` acquires the card separately for each full 100K + 5,120-token arm. Run this orchestrator without a parent GPU lease. It freezes launch sources and the profile once, requires the exact frozen server to have passed the model gate, alternates baseline/candidate then candidate/baseline, and refuses to overwrite failed evidence. `--resume` reuses only validated completed arms and labels them as old evidence. The baseline retains a 3,072 MiB margin; the candidate borrows context memory and requests 2,560 MiB after prompt return.

The declared primary measure is request completion time excluding startup. Acceptance uses an exact one-sided paired sign test at 8 and 16 pairs with a two-look Bonferroni correction, adjusted p <= .01; ties count as nonwins. It stops for futility when the remaining pairs cannot meet that threshold. Reaching the release throughput targets is reported separately from a statistically accepted speed gain. Each arm waits for 53 GiB available RAM outside the card lock, has a 1,460-second deadline, retains the 7 GiB running floor and 23,552 MiB card cap, and requires actual expert device dispatch and positive context borrowing in the candidate. The owner permits n-gram lookup-table (PLE) reads from NVMe when reported. All other model weights must remain resident; unidentified final request bytes reject acceptance. Full context arms follow the shipping reference arms and helper measurements in `NEXT_24H.md`. The current runtime must pass its required model gates before speed acceptance; reaching the admission threshold alone does not release the queue.
