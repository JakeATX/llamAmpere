# Flash-Next startup expert profile

`flash-next.profile` uses the MOEPROF1 usage-count format from fn/fast. Its model identity and checksum are verified before any expert is warmed. The loader does not change a single quantized weight block.

The shipped profile was measured on coding, agentic, and retrieval workloads. Startup fills the first layer first, including unobserved experts, since it has no preceding routing layer for prefetch. It orders the later layers by each tensor's measured use rates per expert byte, with a boost of `1 + 4/(layer + 1)` for early layers, and fills unused capacity in that order. A user-supplied `--moe-profile FILE` takes precedence over this default. To persist new measurements, retain the existing `GGML_MOE_CACHE_PROFILE_SAVE=/mnt/models/<task>/local.profile` setting. On the next startup, pass `--moe-profile /mnt/models/<task>/local.profile`; loading a profile does not overwrite the shipped default.

The arena uses one pinned host allocation and three strided tensor views per layer. Set `--moe-arena off` to retain the original loading path, or `--moe-arena on` to require the arena and fail clearly when the startup memory check does not pass. With no flag it is enabled only when the complete host arena fits with 7 GiB of startup headroom. Loading stops below 7 GiB available host memory. Automatic in-memory prompt caching preserves 11 GiB after load; disk prompt-cache serialization remains supported.

The automatic card budget is free VRAM after model weights, target and draft KV, and MTP allocations, less 2,560 MiB for compute workspaces and a reserve. An explicit `GGML_CUDA_MOE_CACHE_RESERVE_MB` setting overrides that reserve. This value follows the home card's short-prompt workspace gate; a 1,536 MiB reserve exceeded the required whole-card VRAM cap.

For 100K MTP prefill, `LLAMA_MOE_ARENA_OUTPUT_DIR=/mnt/models/<task>/output` opts into file-backed host output when the unmasked next-token embedding buffer grows past 256 MiB, and file-backed in-call checkpoint storage above 64 MiB. Create that directory on a disk with enough free space. This keeps all original float and checkpoint bytes in immediately unlinked, reserved temporary files; it does not change or unpin expert weights. Completed outputs are flushed before MTP reads them, and checkpoints before serialization, allowing the operating system to reclaim their clean file pages. Small outputs still use the existing pinned buffer. This option remains off until the full load/restart and speed gates pass.

Arena prefill staging is capped at the largest single expert role, since an interleaved upload already stops at each role boundary. Checkpoint layouts are sized before allocation to avoid vector capacity growth and additional copies. Their serialized format is unchanged.
