# FNPREFETCH validation on the shared home card

These runners target the authorized `/mnt/models/fnprefetch` worktree and keep artifacts beneath its `protocol`, `logs`, and `cache` directories. They require the active system guard. They never stop another unit. Build the `test-moe-cache`, `test-backend-ops`, `test-moe-prefetch-model`, and `llama-server` targets before freezing a release.

`launch.py` takes the shared card lock before creating an owned `llama.cpp-fnprefetch-*` systemd unit. Set `FN_RUNNER` to the desired gate and pass a unique cell label. Development windows default to 580 seconds. Full arms use 1,480 seconds plus bounded cleanup, at most 25 minutes total. Resource monitoring stops an owned run below 7 GiB available RAM, above 23,552 MiB whole-card VRAM, or below the required disk floors.

Run `gpu-gate.py` in its own lease, then `certify.py` twice with cell labels and stages `model` and `reload`. Explicitly set `FN_GATE_BIN` and `FN_BASELINE_BIN` to frozen release directories; neither stage follows a mutable latest-build pointer. The model stage checks every flag against prefetch off and current frozen ship, validates copy timestamps, requires consumed predictions, and checks exact saved state. The reload stage requires matching model certification before exercising two turns and fresh-process reload. Host provider 0 is the accepted default; device provider 1 needs separate active-table and dispatch evidence. Earlier `followup-gate.py` and `host-followup.py` preserve historical diagnostic recipes only.

The fixed fixture must exist at `protocol/golden-ids.bin`. Build the helper inside the normal locked build unit with `FN_BASELINE_COMMIT=<frozen ship commit> scripts/fnprefetch/prepare-baseline.sh`. This uses that commit's public/common headers and DSOs. Live libraries are verified. Partial artifacts do not count as completion.

After correctness, run `selection-gate.py` in a separate development lease, then `preflight-gate.py` for matched 100K capacity. `run-pairs.py` admits one full arm at a time with alternating AB/BA order. `summarize.py` refuses incomplete arms, changed binaries/settings/profile, overlapping arms, and wrong prompt/output counts. Acceptance uses the predeclared anytime paired sign bound in `full-plan.json`; short diagnostics and synthetic harness checks are never speed evidence.

The profile is copied into this worktree and hashed. Both arms must load it with sampled model-weight identity verification at generation handoff and keep its bytes unchanged. Prefetch defaults off. All output uses temperature 1.0, the same input IDs and sampling settings, the MTP head, and SJ-KVaRN 4/4 for full comparisons.

`fnmiss-priority.patch` is an integration patch to apply after merging both runtime branches. It requires this branch's `device.urgent_transfers` field and prediction records. It adds one node-owned urgent-transfer claim before RAM packing/H2D in each miss path, releases after completion or synchronized failure cleanup, marks only complete cached rows as consumed, and preserves terminal logs for prediction jobs taken over by demand staging. `fnmiss-priority-source.json` hashes the FNMISS files used to prepare it. Application was checked in an owned copy; combined CUDA/model correctness and non-noop miss/prefetch gates remain required before enabling both features.

`validate-and-benchmark.py` waits outside the card lock for the exact candidate's three operator results and matching baseline helper, then advances model, reload, selection, capacity, and full paired stages. Set both explicit build directories. Each stage gets a new bounded card lease, and any failed stage stops the chain. Its progress and error artifact is `logs/chain-<candidate>.json`.
